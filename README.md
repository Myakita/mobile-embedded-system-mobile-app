# Мобильное приложение системы мониторинга личного состава

Android-клиент распределённой отказоустойчивой системы тактического мониторинга состояния и пространственного положения личного состава подразделения.

Приложение функционирует в автономном режиме без выделенного прикладного бэкенда: агрегация данных, вычисление дедупликации, проверка криптографических подписей и хранение топологии сети производятся непосредственно на мобильном терминале оператора.

---

## 1. Архитектурный профиль и стек

* **Среда выполнения:** Android 8.0+ (API Level 26 — 37), Single-Activity + Navigation Component.
* **Язык и среда компиляции:** Java 17 (source/target compatibility), JDK 25 для сборочного контура (Gradle 9.6).
* **Слой представления (UI/Presentation):** View Binding, Material Components 3, Custom Views (`HoldToConfirmButton`), реактивные подписки через AndroidX `ViewModel` + `LiveData`.
* **Картография и геоданные:** `MapLibre Native Android SDK (v11.5.1)`, локальный рендеринг векторных/растровых тайлов без обращения к внешним CDN.
* **Хранилище данных (Persistence):** `Room ORM (v2.6.1)` поверх SQLite (песочница приложения).
* **Криптографическая защита:** `Android Keystore Provider` (аппаратная изоляция ключей, профили AES-128-GCM, AES-256-GCM, ChaCha20-Poly1305).
* **Сетевые каналы связи:**
  * **Основной (Pub/Sub):** `Eclipse Paho MQTTv3 (v1.2.5)` через TLS c взаимной аутентификацией/ACL на брокере.
  * **Прямой аварийный (Direct TCP):** `DirectConnectionManager` для сопряжения с Edge-маршрутизатором (`RouterD`) по ad-hoc Wi-Fi каналу при потере брокера.

## 2. Назначение и целевая аудитория

Приложение предназначено для оператора или командира подразделения, обеспечивая непрерывный ситуационный контроль за физическим состоянием и пространственным положением участников в условиях отсутствия постоянного интернет-соединения или недоступности центрального сервера.

### Основные роли:
* **Оператор / Командир:** мониторинг показателей личного состава на карте и в списках, отслеживание валидности телеметрии, выставление тактических маркеров и отправка директив.
* **Настройщик (Администратор связи):** конфигурирование профилей сетей, сопряжение аппаратных трекеров с идентификаторами бойцов, выбор криптографических профилей.
* **Участник (Источник данных):** носитель носимого терминала/трекера; пассивный генератор телеметрических пакетов.

## 3. Границы функциональности и MVP (MoSCoW)

Минимальный сквозной сценарий MVP:
*Подключение к источнику (MQTT или TCP Direct) → Приём и дедупликация телеметрии → Визуализация на карте и в карточке участника → Определение статуса данных (CURRENT / STALE / UNKNOWN) → Отправка команды подтверждения с защитой от случайного нажатия → Восстановление сессии при обрыве связи.*

### Статус реализации требований:

| Приоритет | Функциональные требования | Статус в кодовой базе |
|---|---|---|
| **Must Have**<br>(Обязательно для MVP) | • Изоляция мультисетей и переключение между ними (US-01)<br>• Привязка устройств к пользователям без коллизий (US-02)<br>• Отображение телеметрии и состояний CURRENT / STALE / UNKNOWN (US-06, US-07)<br>• Отправка базовой директивы `CHECK_IN` (US-08)<br>• Транспорт MQTT (TLS) с автореконнектом (US-09)<br>• Дедупликация телеметрии на клиенте (US-10)<br>• Прямое аварийное TCP-подключение к шлюзу по Wi-Fi (US-11)<br>• Шифрование трафика AES-128-GCM и хранение ключей в Android Keystore (US-12, US-14) | **Реализовано в полном объёме** (`TelemetryRepository`, `MqttTransportManager`, `DirectConnectionManager`) |
| **Should Have**<br>(Желательно) | • Подробная бортовая диагностика пакетов (US-17)<br>• Локальное хранение истории телеметрии в SQLite/Room (US-15)<br>• Офлайн-подложка карты из локальных assets (US-16) | **Реализовано** (БД Room 2.6.1, MapLibre SDK) |
| **Could Have**<br>(Сверх базового MVP) | • Расширенные тактические команды `HOLD` и `RETURN`<br>• Мульти-криптография: AES-256-GCM и ChaCha20-Poly1305<br>• Тревожные триггеры по критическому пульсу/температуре<br>• Вычисление геометрического центра группы, колец дистанции и целеуказание | **Реализовано в коде** (`SquadAlertManager`, `TacticalWaypointManager`) |
| **Won't Have**<br>(Исключено из релиза) | • Синхронизация истории между несколькими планшетами операторов<br>• Централизованный прикладной бэкенд (облачная СУБД)<br>• Динамическая загрузка произвольных регионов карты через Интернет на лету | **Вынесено за рамки проекта** (Архитектурное ограничение) |

## 4. Границы дисциплины и взаимодействие с общей системой

Данный репозиторий изолирован и отвечает исключительно за клиентскую часть на ОС Android. 
Встраиваемое ПО (`RouterD`, носимые маяки), Yocto Linux-сборки и инфраструктура брокера разрабатываются в основном репозитории проекта и выступают для мобильного приложения внешними компонентами.

* Спецификация контрактов и бинарных структур синхронизируется через сабмодуль `protocol/` (формат **LMash v1**).
* Проверка бизнес-логики и разбора пакетов изолирована от Android SDK и проверяется локальными JVM-тестами без эмулятора.

## 6. Сборка и развёртывание

### Требования к хосту
* **JDK:** OpenJDK 25.
* **Android SDK Build Tools:** `37.0.0`.
* **Android SDK Platform:** `android-37`.
* **Gradle:** 9.6 (обслуживается через wrapper `./gradlew`).

### 6.1. Клонирование с зависимостями
Каталог `protocol/` является внешним сабмодулем. Инициализация обязательна:

    git clone --recurse-submodules https://github.com/Myakita/mobile-embedded-system-mobile-app.git
    cd mobile-embedded-system-mobile-app

    # Если репозиторий уже был склонирован без сабмодулей:
    git submodule update --init --recursive

### 6.2. Локальная сборка и статический анализ
Сборка отладочного пакета и прогон тестов бизнес-логики без поднятия эмулятора:

    # JVM Unit-тесты + линтер + сборка APK
    ./gradlew --no-daemon testDebugUnitTest lintDebug assembleDebug

Артефакт сборки генерируется по пути:
`app/build/outputs/apk/debug/app-debug.apk`

### 6.3. Запуск инструментальных тестов
Инструментальные тесты валидируют контракты БД Room и жизненный цикл компонентов. Требуют запущенного Android-эмулятора (рекомендуется API 35/37) или подключенного через ADB физического устройства:

    ./gradlew --no-daemon connectedDebugAndroidTest

## 7. Сетевое взаимодействие и протокол

Обмен пакетами между мобильным клиентом и носимыми терминалами регламентирован контрактом в подмодуле `protocol/` (спецификация **LMash v1**):

1. **Обработка телеметрии (`TelemetryRepository`):**
   * Валидация меток времени: классификация данных по статусам `CURRENT` (актуально), `STALE` (устарело), `UNKNOWN` (потеря связи).
   * Автоматическая дедупликация повторных пакетов из mesh-сети.
2. **Командный интерфейс (`MqttTransportManager`):**
   * Отправка директив (`CHECK_IN`, `HOLD`, `RETURN`) с подтверждением доставки через двухфазный жест интерфейса (`HoldToConfirmButton`).
3. **Автономное прямое сопряжение (`DirectConnectionManager`):**
   * Fallback на локальный сокет TCP при разрыве MQTT-сессии с сохранением буфера неотправленных команд в локальной очереди.
